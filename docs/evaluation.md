## 方法与口径

- 调用真实 `RagService.search`，三种模式共用临时索引；生成接口配置为空，不调用付费 API，不修改应用知识库。
- 证据必须同时匹配文件名和标注原文；全部证据命中率要求该题的每条证据都召回。证据召回率是逐题覆盖比例的平均值。
- MRR 取第一条相关证据的倒数排名，不能证明多证据问题已经获得完整依据。无答案题不进入上述三个指标的分母。
- 无答案题召回率统计这类问题仍返回片段的比例；返回相关条款可能帮助模型拒答，因此此指标不等于回答错误率或拒答失败率。
- dev 用于后续调试，test 作为当前基线；此次没有根据结果调整算法或阈值。题目和文档由同一项目手工编写，两组共享资料，均不是外部盲测。
- 默认一次取前 5 条，再计算 K=1/3/5；这三个 K 的 RRF 候选数均为 20，与直接按对应 K 检索一致。

## 本次发现与下一步

在全部 48 道有答案题上，完整证据命中率@3 分别为 BM25 45/48（93.8%）、向量 47/48（97.9%）、混合 46/48（95.8%）。test 的三种模式均为 25/26，但失败题目不同，不能只看总分选择方案。

- dev 的 `P01` 使用“首都、跑业务、住酒店”等口语表达。向量检索把国内差旅排在第 1，混合检索前 5 条仍未出现它，说明当前相等权重 RRF 可能压低正确结果的排名。
- dev 的 `P02` 在 BM25 前 5 条中没有参考证据，向量排第 1，混合排第 2。这个例子支持继续验证语义召回对口语问法的帮助。
- test 的 `M07` 同时需要离职交接和数据分级。第二份证据在 BM25 排第 5、混合排第 4、向量排第 2，说明多证据问题需要检查覆盖，不能只用第一条相关结果的排名代替。
- test 的 `P11` 在向量中排第 4、BM25 与混合中排第 2，表明向量模型也会漏掉前 3 条；本次没有一种模式在所有问题上都更好。
- 三种模式在 12 道无答案题上均返回了片段。当前系统只在没有检索结果时自动跳过模型；有片段时，是否正确拒答仍需另测，不能由本次检索指标推断。

这份原始基线提出在 dev 上比较“当前融合”和“扩大候选后重排序”，重点复核 `P01` 的排名，同时增加新的口语问法与跨文件问题。后续已实现可选本地重排序并完成比较，详见 [重排序评测](reranking.md)：本次未提升 Top-3 完整证据命中率，因此默认关闭。生成回答的引用支持与无答案拒答另见 [回答评测](answer-evaluation.md)。

## 结论与后续验证

这份报告衡量检索证据的覆盖情况，没有测量生成回答准确率、忠实度、拒答能力或 Token 费用。后续新增的 28 道真实问答实验单独记录在 [回答忠实度与拒答评测](answer-evaluation.md)，请分别看待检索与回答指标。
资料较短，部分题目一条片段即包含全部证据；不能把这里的百分比直接写成真实企业问答准确率。
后续先在 dev 上分析漏召回：同义问题可比较查询改写与重排序，多证据问题可比较问题拆解和分路检索。重排序只能调整已召回候选的顺序，不能补回候选之外的证据。
无答案题应另做“是否有充分依据作答”的回答评测，避免仅提高向量阈值就声称解决幻觉。测试结果已在本报告展示；后续反复依据 test 调参会污染基线，应另增未参与调试的新题。
