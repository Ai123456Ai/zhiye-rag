# 问题拆解：结果与未解决项

本次针对公开回答评测中暴露的跨章节漏召回，加入可选规则分句、各子问题独立检索和轮流合并。实现没有 FastAPI 专用关键词或题号判断，也没有额外调用生成模型。默认关闭。

## 新问法的结果

[固定的 24 道新问法](../evals/public-fastapi/decomposition.json) 包含 18 道有答案题和 6 道自然缺项。同一临时索引、相同 Top-3 最终来源预算、关闭重排序，混合检索完整证据命中从 9/18 到 13/18，多证据题从 4/12 到 8/12；单问题控制保持 5/6。三种模式的具体对照见 [运行报告](query-decomposition.md)，原始来源和子问题见 [JSON](decomposition-run.json)。

混合检索逐题有 5 题改善、1 题退步。退步题 QD01 原本找齐“请求体校验错误反馈”和“成功响应过滤密码”，拆解后挤出了第一条标注证据。BM25 的 QD07 也退步：两篇教程分别使用 limit=10 与 limit=100，轮流合并仍未保证两处具体示例都进入最终来源。因此不能把“已经分成两个问题”视作“已经找到两份充分证据”。

混合检索耗时中位数 18.59 → 38.39 ms；24 次请求的排名计算次数 24 → 54。额外子问题增加计算，最终来源数相同不代表计算预算相同。每题每组只运行一次，时间不表示生产并发性能。

## 已知失败案例没有全部修复

[既有 30 题回归](decomposition-known.md) 使用原 benchmark，问题已经用于分析，不是新测试数据。混合检索完整证据命中仍是 19/24；BM25 为 22/24 → 23/24，向量保持 15/24。开关两组同索引，片段 ID 并列排序可能使重建索引后的细节变化。

- FM02：拆解后虽然出现 handling-errors 与 response-model 两个章节，但响应模型片段并不包含标注要求的过滤说明，仍未完整命中。
- FM05：混合检索拆解后的“失败时用 detail 返回结构化字典”仍未召回所需 handling-errors 证据；BM25 在该题改善。
- 开发集 FM01：原问题对照 q=None 与模型属性无默认值，拆解后混合检索丢失模型属性必填规则，发生退步。

这些现象说明还需检查子问题本身的检索质量、分块和候选选择。此次没有在观察新题结果后继续调整规则，也没有宣称最初两个失败案例已修复。

## 使用边界

规则只识别明确标点和连接词，保护反引号、双引号及中文引号内的内容。复杂指代、条件、比较和省略句可能被误拆，未加引号的分号也可能形成边界。过短、重复、超过三个子句，或来源数少于子问题数时回退原检索。它不理解问句语义，不验证各部分证据是否充分。

各查询分别按 BM25、向量或混合检索；重排序开启时各自重排后合并。轮流合并优先每个子问题，再补原问题，只按片段 ID 去重，保留不同文档和版本的来源。它没有跨查询统一相关性分数，也没有保证每个子问题分到的片段都正确。

现有版本筛选在所有查询之前执行；版本歧义仍暂停模型生成。新功能的版本过滤、三种检索与重排序组合、引用连续性、API 参数和模拟生成测试均使用临时数据与模拟接口，不产生费用。

6 道新缺项题仍全部召回片段，本轮未重新调用模型验证拒答。原公开回答、评审及其代码哈希保留原样，不能拿旧回答评测为新提示词和检索策略背书。

新题是项目自编问法，写于规则实现后、首跑前，部分概念来自已知资料和旧标签，规模也小。本次仅证明在此固定题集上存在检索收益与退步；需要更多独立问题、等价证据复核与实际回答评审，才能继续判断适用性。
